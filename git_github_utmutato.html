1. Git vs GitHub

A Git egy verziókezelő program, ami a saját gépeden fut, és nyomon követi a fájlok változásait az idő során. A GitHub egy felhő alapú szolgáltatás, ahol ezeket a Git-repókat tárolod, megosztod másokkal, és együtt dolgozol rajtuk. Vagyis: Git = az eszköz, GitHub = a felhő, ahol a munkádat tárolod és megosztod.
GitGitHub
Helyi programfüggetlen verziókezelőOnline platform Git-repók tárolására
Parancssorból (terminál) használjukBöngészőben és parancssorból is elérhető
Nincs szükség internetreInternetkapcsolat kell hozzá

2. Telepítés és első beállítás

Telepítés után első lépésként be kell állítani a nevedet és email-címedet — ez fog megjelenni minden commit mellett szerzőként.
Alapbeállítás (egyszer kell, gépenként)
git config --global user.name "Teljes Neved"
git config --global user.email "email@pelda.hu"

# ellenőrzés
git config --list
A --global kapcsoló azt jelenti, hogy ez a beállítás minden repóra érvényes lesz ezen a gépen. Repónkénti egyedi beállításhoz hagyd el a --global-t, és a repó mappájában futtasd.

3. Helyi és távoli repó (local vs remote)

A helyi repó a saját géped mappájában lévő .git mappa, ami tárolja a projekt teljes történetét. A távoli repó (remote) ennek egy másolata a szerveren (pl. GitHub-on). A kettő között a push és pull parancsokkal mozgatjuk az adatokat.

4. Új repó létrehozása

Kétféleképp indulhatsz: (A) létrehozod a repót GitHub-on, és onnan klónozod le magadhoz; vagy (B) van egy helyi mappád, amit te alakítasz repóvá és töltesz fel (lásd 5. pont).
1
GitHub-on kattints a jobb felső "+" ikonra → New repository. Adj neki nevet, válaszd, hogy publikus vagy privát legyen, opcionálisan pipáld ki a "README" és ".gitignore" hozzáadását.
2
A repó létrehozása után GitHub megadja a klónozáshoz szükséges URL-t (HTTPS vagy SSH).
Frissen létrehozott repó leklónozása a gépedre
git clone https://github.com/felhasznalonev/repo-neve.git
cd repo-neve

5. Meglévő (helyi) mappa feltöltése GitHub-ra

Ha már van egy kész projekt-mappád a gépeden, és ezt szeretnéd feltölteni egy (üres) GitHub repóba, az alábbi lépéseket kövesd.
1
Hozz létre egy üres repót GitHub-on (README nélkül, hogy ne legyen ütközés).
2
Nyisd meg a terminált a mappádban, és inicializáld Git-tel.
3
Kapcsold össze a helyi mappát a távoli (remote) repóval.
4
Add hozzá a fájlokat, commitold, majd told fel (push).
Meglévő mappa feltöltése lépésről lépésre
cd utvonal/a/mappahoz

git init                          # mappa Git-repóvá alakítása
git add .                         # minden fájl staging-be helyezése
git commit -m "Első feltöltés"    # commit létrehozása

git remote add origin https://github.com/felhasznalonev/repo-neve.git
git branch -M main                # az ág átnevezése "main"-re
git push -u origin main           # feltöltés + a kapcsolat rögzítése
A -u (upstream) kapcsoló csak az első push-nál kell — ez után elég simán git push-t írni, a gép emlékszik, hova kell tölteni.

6. Alap munkafolyamat: add → commit → push

Ez a napi rutin: módosítod a fájlokat, jelölöd, mi kerüljön be a következő mentésbe (add), elmented egy névvel ellátott állapotot (commit), majd feltöltöd a szerverre (push).
Napi munkafolyamat
git status                  # mi változott?
git add fajl.txt            # egy adott fájl jelölése
git add .                   # összes változás jelölése
git commit -m "Üzenet arról, mit csináltál"
git push                    # feltöltés a távoli repóba
Hasznos ellenőrző parancsok
git status      # mi módosult / mi van staging-ben
git log         # commit-történet
git diff        # pontosan mi változott a fájlokban

7. Meglévő repó letöltése (clone)

Ha egy már létező GitHub-repót szeretnél a gépedre letölteni (akár a sajátod, akár másé, amin dolgozni szeretnél), a clone parancsot használod.
Klónozás
git clone https://github.com/felhasznalonev/repo-neve.git

# adott mappanévvel:
git clone https://github.com/felhasznalonev/repo-neve.git sajat-mappanev

8. Branch-ek és a main

A branch (ág) egy önálló fejlesztési vonal. A main (régebben master) az elsődleges, "éles" ág. Új funkciókat gyakran külön branch-en fejlesztünk, hogy a main mindig stabil maradjon, majd a kész munkát összeolvasztjuk (merge).
Branch-műveletek
git branch                     # meglévő branch-ek listázása
git branch uj-funkcio           # új branch létrehozása
git checkout uj-funkcio         # átváltás a branch-re
git checkout -b uj-funkcio      # létrehozás + átváltás egyben

# újabb Git verzióban:
git switch uj-funkcio
git switch -c uj-funkcio        # létrehozás + váltás

git checkout main               # vissza a main ágra
git merge uj-funkcio            # a "uj-funkcio" beolvasztása a mainba

git branch -d uj-funkcio        # branch törlése (ha már mergelve van)
git push origin uj-funkcio      # branch feltöltése GitHub-ra
Csapatmunkánál jellemzően nem közvetlenül a main-be dolgozunk: branch-et hozunk létre, ott fejlesztünk, majd GitHub-on Pull Requesttel kérjük a beolvasztást (lásd 15. pont).

9. Remote kezelés, váltás repók között

Egy mappa (helyi repó) tetszőleges számú távoli repóhoz kapcsolódhat, de alapesetben egy van, "origin" néven. Ha másik repóra szeretnéd irányítani ugyanazt a mappát (pl. átköltöztetted a projektet egy másik GitHub-repóba), a remote URL-t kell megváltoztatnod.
Remote-ok listázása és kezelése
git remote -v                       # jelenlegi remote-ok listázása

# remote URL cseréje (pl. másik repóra váltás ugyanabban a mappában)
git remote set-url origin https://github.com/masikfiok/masik-repo.git

# új remote hozzáadása más néven (pl. ha egyszerre 2 helyre push-olnál)
git remote add masodikrepo https://github.com/felhasznalonev/masik.git
git push masodikrepo main

# remote eltávolítása
git remote remove masodikrepo
Repók közötti váltás a gépeden valójában azt jelenti, hogy más mappában dolgozol: minden repónak saját mappája és saját .git könyvtára van. Egyszerűen cd-zel lépsz át a másik projekt mappájába — nincs "aktív repó" fogalom Git szinten, mint pl. egy adatbázis-kapcsolatnál.

10. Fetch vs Pull vs Push

ParancsMit csinál
git fetchLetölti a távoli repó változásait, de nem egyesíti a saját munkáddal — csak "megnézed", mi változott.
git pullfetch + merge egyben: letölti és azonnal egyesíti is a saját ágaddal.
git pushFeltölti a helyi commit-jaidat a távoli repóba.
Példa
git fetch origin          # csak letölti, nem érinti a munkádat
git pull origin main      # letölti és beolvasztja a main ágba

11. Ütközések kezelése (merge conflict)

Ha két branch ugyanazt a sort módosította más módon, Git nem tudja automatikusan eldönteni, melyiket tartsa meg — ez a merge conflict. Ilyenkor a Git megjelöli a fájlban az ütköző részeket, neked kell kézzel eldönteni, mi maradjon.
Ütköző fájlban megjelenő jelölés
<<<<<<< HEAD
Ez a te verziód
=======
Ez a másik branch verziója
>>>>>>> uj-funkcio
Feloldás menete
# 1. szerkeszd a fájlt, döntsd el mi maradjon, töröld a <<<</====/>>>> jeleket
# 2. jelöld megoldottnak:
git add fajl.txt
# 3. fejezd be a merge-et:
git commit

12. .gitignore

A .gitignore fájlban felsorolt fájlokat/mappákat a Git figyelmen kívül hagyja — nem kerülnek be a verziókezelésbe. Ide kerülnek tipikusan a telepített csomagok, titkos fájlok, ideiglenes fájlok.
Példa .gitignore tartalom
node_modules/
.env
dist/
*.log
.DS_Store

13. Hitelesítés: HTTPS vs SSH

A GitHub-hoz kétféleképpen kapcsolódhatsz: HTTPS (felhasználónév + személyes hozzáférési token, Personal Access Token) vagy SSH kulcs (egyszer beállítod, utána jelszó nélkül működik).
SSH kulcs generálása és hozzáadása
ssh-keygen -t ed25519 -C "email@pelda.hu"
# Enter-rel elfogadod az alapértelmezett helyet

cat ~/.ssh/id_ed25519.pub
# a kimenetet másold be: GitHub → Settings → SSH and GPG keys → New SSH key

# tesztelés:
ssh -T git@github.com
SSH-s klónozásnál a repó URL-je nem https://..., hanem git@github.com:felhasznalonev/repo.git formátumú.

14. Több GitHub fiók kezelése egy gépen

Ha pl. egy személyes és egy munkahelyi GitHub fiókod is van ugyanazon a gépen, SSH-alapú megoldással tudod tisztán elkülöníteni őket: fiókonként külön SSH-kulcsot generálsz, és egy ~/.ssh/config fájlban megadod, melyik kulcsot melyik "host-alias" használja.
1. lépés: két külön SSH kulcs generálása
ssh-keygen -t ed25519 -C "szemelyes@email.hu" -f ~/.ssh/id_szemelyes
ssh-keygen -t ed25519 -C "munkahelyi@ceg.hu" -f ~/.ssh/id_munkahelyi
2. lépés: ~/.ssh/config fájl beállítása
Host github-szemelyes
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_szemelyes

Host github-munka
  HostName github.com
  User git
  IdentityFile ~/.ssh/id_munkahelyi
3. lépés: klónozás/remote a megfelelő host-aliasszal
# személyes fiók repójánál:
git clone git@github-szemelyes:felhasznalonev/repo.git

# munkahelyi fiók repójánál:
git clone git@github-munka:cegnev/repo.git

# meglévő repónál a remote átállítása a másik fiókra:
git remote set-url origin git@github-munka:cegnev/masik-repo.git
Bónusz: repónkénti eltérő név/email beállítása
# a repó mappájában (nem --global!):
git config user.name "Munkahelyi Nev"
git config user.email "munkahelyi@ceg.hu"
HTTPS-sel is megoldható több fiók (pl. Windows Credential Manager-ben tárolt több token, vagy a gh auth switch parancs a GitHub CLI-vel), de gépenként, csapatban dolgozva az SSH host-alias módszer a legátláthatóbb.

15. Fork és Pull Request (csapatmunka)

Ha egy olyan projektbe szeretnél hozzájárulni, amihez nincs írási jogod, először fork-olod (saját fiókodba másolod a repót), ott dolgozol, majd Pull Requestet (PR) nyitsz, hogy az eredeti projekt tulajdonosa beolvaszthassa a változtatásaidat.
1
GitHub-on kattints a Fork gombra az eredeti repón → létrejön egy másolat a saját fiókodban.
2
Klónozd le a saját forkodat, és állítsd be az eredetit "upstream"-ként.
3
Dolgozz egy branch-en, commitolj, push-old fel a saját forkodba.
4
GitHub-on nyiss Pull Requestet a saját branch-edből az eredeti repó main ágára.
Fork + upstream beállítás
git clone https://github.com/sajatfiokod/repo.git
cd repo
git remote add upstream https://github.com/eredeti-tulajdonos/repo.git

# az eredeti repó változásainak lekérése és beolvasztása:
git fetch upstream
git merge upstream/main

Bónusz Weboldal működtetése GitHub-on (GitHub Pages)

A GitHub Pages egy ingyenes szolgáltatás, amivel egy statikus weboldalt (HTML, CSS, JS) közvetlenül a GitHub-repódból tehetsz élesbe, saját github.io címen.
1
Töltsd fel a weboldal fájljait (legalább egy index.html-t) a repóba.
2
GitHub-on menj a repó Settings → Pages menüpontjába.
3
A "Source" résznél válaszd ki a branch-et (általában main) és a mappát (/root vagy /docs).
4
Mentés után néhány percen belül élesedik az oldal a https://felhasznalonev.github.io/repo-neve/ címen.
Tipikus repó-struktúra GitHub Pages-hez
repo-neve/
├── index.html
├── style.css
├── script.js
└── images/
Ha React/Vue/build-elt projektet szeretnél kitenni, először le kell futtatni a build parancsot (pl. npm run build), és a build eredményét (általában a dist vagy build mappát) kell publikálni — vagy a gh-pages npm csomagot használhatod erre automatikusan.
